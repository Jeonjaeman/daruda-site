DARUDA 레퍼런스 보드

"일반적인 인테리어 스튜디오 사이트의 뼈대를 갖추되, 한두 군데만 독특한" 사례를 모았습니다. v1의 어디가 이용자에게 낯선지 먼저 짚고, 그 문제를 각 레퍼런스가 어떻게 푸는지 적었습니다. 캡처는 2026-10-21 기준 실제 화면입니다.

v1이 낯선 이유 — 이용자 관점 5가지

v1은 의뢰자 기획안을 그대로 옮긴 결과라 아래 지점에서 "이게 뭐지?"가 생깁니다.

1. 메뉴가 화면 맨 아래에 흩어져 있다

이용자는 로고 옆이나 오른쪽 상단에서 메뉴를 찾습니다. 하단 네 귀퉁이에 소문자로 흩어진 메뉴는 캡션처럼 읽혀 클릭 대상인지 모릅니다.

2. about·press·contact가 페이지가 아니라 '오버레이'

마우스를 올리기만 해도 흰 사각형이 튀어나오고, 주소(URL)도 바뀌지 않아 공유·뒤로가기가 안 됩니다. 모바일에서는 '오버'가 없어 동작이 달라집니다.

3. 'U' 마커, P / A 아웃라인 글자

로고의 U, archive의 거대한 P·A는 내부 사람에겐 의미가 있지만 처음 온 사람은 무엇을 뜻하는지 알 수 없고, ( 4 ) ( 53 ) 숫자는 설명이 없습니다.

4. 작업물에 닿기까지 3단계

메인 → archive → PROCESSING/ARCHIVING → LIVING/COMMERCIAL 행 → 프로젝트. 포트폴리오 사이트의 핵심인 "사진 보기"까지 클릭이 너무 많습니다.

5. 사진이 설명 없이 움직인다

메인 슬라이드에 프로젝트명이 없어 "이게 이 회사 작업인가, 분위기 사진인가"를 알 수 없습니다. stof·Norm은 사진마다 제목 한 줄을 붙입니다.

1순위 레퍼런스 — 일반적인 뼈대 + 독특한 한 수

DARUDA 톤(흰 벽·대리석·굵은 로고·Pretendard)과 가까우면서, 상단 메뉴·작품 그리드·상세 페이지라는 통상 구조를 지킨 사이트입니다.

Norm Architects

normcph.com
  • 메인: 풀스크린 사진 슬라이드 + 사진 하단에 프로젝트명과 한 줄 설명, 아래 점(•) 인디케이터. 의뢰자가 원한 "풀이미지 무빙"을 유지하면서 사진에 이름이 붙습니다.

v2 방향 제안 (의견 주시면 그대로 반영)

의뢰자 기획안의 '독특한 장치'는 살리되, 뼈대는 Norm·WGNB·Fenomen처럼 일반형으로 바꾸는 두 가지 안입니다.

추천 A

Norm형 — 풀이미지 + 상단 바 + 미색 그리드

  1. 상단 바: DARUDA 로고(좌) · about / archive / press / contact(우). 사진 톤에 따라 글자색 자동 전환(v1 기능 유지).
  2. 메인 풀이미지 슬라이드 유지. 단 사진 하단에 프로젝트명 + 한 줄 캡션과 점 인디케이터 추가.
  3. about·press·contact는 페이지로. 데스크톱에서는 흰 패널이 오른쪽에서 슬라이드되는 '패널 페이지'로 기획안 느낌 유지, 주소는 바뀜.
  4. archive = 미색 배경 그리드 한 페이지. 상단 필터 ALL / LIVING / COMMERCIAL / PROCESSING, 머리에 "( 53 ) completed · ( 4 ) in progress". P·A 아웃라인 글자는 필터 옆 장식으로 축소.
  5. 상세 = stof 메타 리스트 + salad-bowl 가로·세로 혼합 서브 이미지.
  6. 마퀴(THIS IS WHAT WE'RE MAKING)는 PROCESSING 필터 선택 시에만 하단에 등장.
대안 B

WGNB형 — 분할 히어로 + 드롭다운

  1. 상단 바 동일. archive 메뉴에 드롭다운(processing / living / commercial / press).
  2. 히어로 좌측에 프로젝트명이 겹쳐 지나가는 큰 타이포(v1의 'U' 마커·아웃라인 타이포를 이 자리로 옮김), 우측 사진 슬라이드.
  3. 스크롤 첫 화면 하단에 최근 작업 썸네일 행이 보이도록 높이 조정.
  4. 나머지(상세·press·contact)는 A안과 동일.
